# 実装と検証の状況

正式資料 `AIニュース風刺画端末_要件定義とシステム設計_v0.1.md` はユーザーが `docs/` に配置しました。UTF-8、44,455バイト、556行で読め、Libraryで読んだ本文と末尾改行を除いて一致します。原本は変更していません。以下は実装済み構成と導入前の確認項目です。

## 1. 入力資料と設計照合

1. 正式 Markdown の存在、可読性、内容を確認済み。
2. 参考の V4 ドライバー正常系（init/display/sleep）を確認する。古い V3 記述、壊れた fast 経路、コンストラクタでの即 init、無期限 BUSY 待ちは流用しない。
3. Wi-Fi 認証情報を含む参考 `main(20261003-084351).py` は内容や認証値を表示、複写、Git 保存しない。
4. 母艦と Pico のプロトコル、整合性検証、失敗時の状態遷移を正式設計書と照合する。追加HMAC認証は後続のユーザー指定で採用しない。

## 2. 母艦側

1. 毎時ジョブで面白い最新AIニュースを調査し、出典と日時を記録する。既出ニュースまたは新ネタがない場合は更新をスキップする。
2. Codex ヘッドレス GPT-6-Luna に構想を作らせる。画像生成バックエンドを分離し、実際に画像生成ツールを利用できるか検証するゲートを設ける。利用不可なら明示的に失敗させる。
3. 画像を `250×122` の1bit PNGへ確定し、全履歴、出典、日時、モデル情報を永続保存する。PNG から RAW への変換を一元化する。
4. 最終 RAW を検証した後、最新 manifest を原子的に切り替える。HTTP サーバは保存済み manifest と RAW の配信に専念させる。

## 3. Pico W 側

1. 毎時ウェイク、Wi-Fi 接続、最新版の PULL、変更時だけ描画、パネル sleep、Wi-Fi 停止、省電力待機を実装する。
2. RAW は物理 `122×250`、1行16バイト、合計4000バイト、MSB先、白1・黒0、未使用ビット白とする。論理 `250×122` からの回転と Landscape 表示順を固定する。
3. 通信の長さとハッシュを検証し、同一フレームは再描画しない。通信失敗時に無条件 Clear しない。
4. Wi-Fi、HTTP、BUSY、ウェイク全体に有限の期限を設け、再試行と後片付けを実装する。

## 4. 単体テストと受入前確認

- PNG 寸法・1bit 化、RAW の長さ・極性・padding、角マーカーと縦横パターンによる回転の golden vector。
- manifest の原子的切替、履歴保存、重複ニュースと新ネタなしのスキップ、画像生成不可時の失敗。
- Pico の短い受信、ハッシュ不一致、HTTP 失敗、BUSY 期限切れ、同一フレーム再取得時の挙動。
- 最終コードに対する単体テストを実行し結果を記録する。
- 実機の画面方向、BUSY 挙動、Wi-Fi 停止、消費電力、バッテリー寿命は別途確認する。これらは未検証として扱う。
